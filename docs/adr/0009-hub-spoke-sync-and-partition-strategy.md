# 9. Hub-Spoke Synchronization and Directory Partitioning Strategy

We decided to establish a hybrid synchronization and directory partitioning strategy ("Git Core - Cloud Artifacts") to manage the flow of tri thức between the central Hub and downstream Spoke workspaces. Lightweight, diffable, and globally shared text assets (platform code, skill definitions, workflows, cẩm nang guidelines, and session learnings) are synchronized using Git repository tracking. Conversely, specific project deliverables (such as Word .docx outputs, PDFs, and raw media frames) are placed in a dedicated, Git-ignored folder under `.md/projects/` and synchronized via cloud storage clients (OneDrive and SharePoint). To prevent concurrent sync conflicts during teamwork or multi-agent execution, only the main Orchestrator agent is permitted to write finalized deliverables to the synced folder, while subagents write to isolated local sandboxes. Furthermore, to prevent credential leakage on local Spoke Git repositories, a local pre-commit hook is dynamically written to `.git/hooks/pre-commit` to run the Maskara privacy tool automatically during Spoke initialization via `/ccba-init-spoke`. This strategy keeps the Git history free of binary bloat while maintaining seamless accessibility of deliverables.
